# Converty

[English](README.md) | [Türkçe](README.tr.md) | [Deutsch](README.de.md) | [简体中文](README.zh-CN.md) | العربية | [Português](README.pt.md) | [Français](README.fr.md) | [Русский](README.ru.md)

Converty هو تطبيق Android لتحويل الملفات محلياً على الجهاز. يعتمد على Storage Access Framework وWorkManager وواجهة Material 3 Expressive. يدعم ملفاً واحداً أو عدة ملفات، واختيار صفحات أو شرائح محددة، وسجل تحويل دائم، وفتح النتائج أو مشاركتها مباشرة.

المشروع قيد التطوير النشط. يحافظ تحويل PDF إلى PPTX على مظهر الصفحة بوضع صورة الصفحة المعروضة داخل الشريحة، ولذلك لا يكون النص قابلاً للتحرير. أما تحويل PPTX وملفات Office إلى PDF فيدعم مجموعة عملية محدودة من المحتوى ولا يدّعي مطابقة عرض Microsoft Office بالكامل.

## الحالة الحالية

- معرّف التطبيق: `com.converty.app`
- الحد الأدنى: Android 6.0، المستوى 23
- Target وCompile SDK: المستوى 37
- الواجهة: Jetpack Compose وMaterial 3 Expressive
- المعالجة: محلية على الجهاز
- التحقق الحالي: 80 اختبار JVM و7 اختبارات instrumentation على جهاز Android
- حالة النشر العام: المصدر مهيأ للنشر بموجب Apache-2.0 وتم إنتاج إصدار release موقّع محلياً؛ إعداد F-Droid لم يكتمل بعد.

## الميزات الأساسية

- اختيار ملف واحد أو عدة ملفات في العملية نفسها.
- تحويلات خلفية عبر WorkManager مع تقدم لكل ملف ولكل مهمة.
- سجل محلي للمهام الناجحة والفاشلة والملغاة.
- فتح كل ملف ناتج أو مشاركته من شاشة السجل.
- اختيار مجلد الإخراج بواسطة منتقي الملفات في Android.
- معالجة كل الصفحات أو الشرائح، أو أول وآخر N عناصر.
- دعم نطاقات منفصلة مثل `1,3-5,9` مع إبقاء نطاقات محددة أو استبعادها.
- إعداد الجودة وDPI وWebP بدون فقد وخيارات ملاءمة الصورة عندما يدعم مسار التحويل ذلك.
- سمات النظام والفاتح والداكن والألوان الديناميكية ولوحات ألوان متعددة.
- واجهة بالإنجليزية والتركية والألمانية والصينية المبسطة والعربية والبرتغالية والفرنسية والروسية.
- تخطيط RTL للعربية وأيقونات adaptive وأيقونة أحادية اللون لنظام Android 13.

## التحويلات المدعومة

### المستندات والعروض

| المصدر | الهدف | الملاحظات |
|---|---|---|
| PDF | PPTX | عرض كل صفحة مختارة كصورة داخل شريحة؛ النص غير قابل للتحرير. |
| PPTX | PDF | يدعم النصوص والصور والتعبئة والخطوط والأشكال الأساسية؛ قد تظهر تحذيرات للميزات غير المدعومة. |
| DOCX | PDF | يدعم المحتوى الأساسي؛ قد يختلف التخطيط المعقد عن Microsoft Word. |
| XLSX | PDF | يدعم محتوى الجداول الأساسي؛ التخطيط المتقدم والحسابات محدودان. |
| ODT وODS وODP | PDF | يعرض محتوى OpenDocument المدعوم محلياً. |

### مخرجات PDF والصور

- PDF إلى PNG وJPG وTIFF وصورة JPEG مصغرة.
- PNG إلى JPG أو WebP.
- JPG إلى PNG أو WebP.
- WebP إلى PNG أو JPG.
- TIFF وBMP إلى PNG أو JPG.
- HEIC وHEIF إلى PNG أو JPG.
- SVG إلى PNG.
- AVIF إلى PNG أو JPG أو WebP.

قد يختلف دعم HEIC وHEIF وAVIF وTIFF وWebP حسب إصدار Android وتنفيذ الجهاز.

## التحديد والتحكم في الإخراج

يمكن لملفات PDF وPPTX معالجة الكل، أو أول N، أو آخر N، أو نطاقات يتم إبقاؤها أو استبعادها، أو عدة نطاقات منفصلة في عملية واحدة. يدعم PDF إلى PPTX أوضاع contain وcover وstretch. تدعم مسارات PDF المناسبة قيمة DPI من 72 إلى 600. تتم حماية أسماء النتائج مع الحفاظ على أسماء Unicode.

## الخصوصية والتخزين

لا يطلب التطبيق الحالي إذن Android المسمى `INTERNET` ولا يتضمن إعلانات أو حزم تحليلات. تتم التحويلات على الجهاز، ولا يصل التطبيق إلا إلى الملفات والمجلدات التي يختارها المستخدم عبر منتقي مستندات Android.

يُحفظ السجل والإعدادات محلياً بواسطة Room وDataStore، ويتم استبعادهما من النسخ السحابي ونقل بيانات الجهاز. كما يُمنع اتصال الشبكة غير المشفر في إعدادات التطبيق. يجب مراجعة هذه الفقرة عند إضافة أذونات أو شبكات أو قياس استخدام أو تقارير أعطال.

## القيود المعروفة

- ينتج PDF إلى PPTX شرائح مبنية على الصور ولا يعيد بناء عناصر PowerPoint قابلة للتحرير.
- لا يحل PPTX إلى PDF محل Microsoft PowerPoint أو LibreOffice أو محرك OOXML كامل. قد تكون SmartArt والمخططات والجداول والمجموعات والوسائط والحركات والقوالب والخطوط والتأثيرات غير مكتملة.
- يستخدم DOCX وXLSX وOpenDocument نموذج عرض محلي محدوداً ولا يضمن تطابق الصفحات والتخطيط.
- قد تُرفض الملفات المشفرة أو التالفة أو الضخمة جداً أو المصممة بشكل ضار.
- قد تحتاج الملفات الكبيرة إلى ذاكرة ووقت كبيرين.
- يحتاج العمل foreground في Android 13 وما بعده إلى إذن الإشعارات، لكن رفضه لا يعطل قائمة الانتظار داخل التطبيق.

## البناء من المصدر

المتطلبات: JDK 17 وAndroid SDK Platform 37 وBuild Tools 37.0.0 وGradle Wrapper المرفق. الإصدارات الأساسية هي AGP 9.2.1 وGradle 9.4.1 وKotlin 2.3.10 وCompose BOM 2026.06.00 وMaterial 3 1.5.0-alpha23.

Linux أو macOS:

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

نسخة Release:

```sh
./gradlew assembleRelease
```

تم إعداد توقيع production محلياً عبر `key.properties` وrelease keystore مخصص. يستبعد `.gitignore` الملفين، ويجب عدم إيداعهما في المستودع أو نسخهما إلى الوثائق أو كشفهما في السجلات أو تقارير issues. عند وجود هذين الملفين محلياً، ينتج `assembleRelease` ملف APK موقّعاً. لا تحتوي النسخة العامة النظيفة من المصدر على أي مواد توقيع خاصة، ويمكنها إنتاج release غير موقّع؛ وهذا هو مسار البناء الصحيح لـ F-Droid لأنه يوقّع الملفات الثنائية التي يوزعها بنفسه.

## بنية المشروع

- `core`: عقود التحويل ومنطق التحديد ومحركات التحويل.
- `data`: الوصول إلى الملفات وسجل Room وإعدادات DataStore.
- `work`: WorkManager والتقدم والإلغاء ومحولات worker.
- `feature` و`ui`: شاشات Compose ونظام Material 3 Expressive.
- `res`: الترجمات والسمات والأيقونات وإعدادات Android.
- `src/test` و`src/androidTest`: اختبارات JVM واختبارات الأجهزة.
- `HANDOFF`: ملاحظات البنية والقرارات والتحقق.

## حالة النشر

شجرة المصدر مهيأة للنشر على GitHub بموجب Apache License 2.0. تم إعداد مفتاح production مخصص محلياً فقط، وتم إنتاج release APK موقّع. لا تدخل ملفات التوقيع الخاصة عمداً ضمن شجرة المصدر العامة.

يجب اعتبار APK الموقّع الحالي مرشح release محلياً، وليس حزمة جاهزة لـ F-Droid. تبقى الأعمال التالية قبل التقديم إلى F-Droid أو نشر حزمة عامة دائمة:

1. استبدال `com.converty.app` بمعرّف تطبيق دائم وفريد عالمياً. هذا المعرّف مستخدم بالفعل من تطبيق آخر غير ذي صلة، ولذلك سيؤدي النشر به إلى تعارض في هوية التطبيق.
2. نُشر فرع `main` العام على [GitHub](https://github.com/mmgecer/Converty-Android). ما يزال يلزم إعداد وpush وسم `v0.1.0` المطابق تماماً للمصدر المقدم.
3. إضافة بيانات بناء F-Droid، بما في ذلك ربط الإصدارات ووصفة بناء تعتمد بالكامل على المصدر.
4. إعادة البناء من checkout نظيف على Linux داخل بيئة شبيهة بـ F-Droid واجتياز فحوص scanner وقابلية إعادة البناء الخاصة به.
5. إكمال المراجعة النهائية للأصول وتراخيص الاعتماديات، وإضافة أي إشعارات أو نسب يحددها التدقيق.
6. زيادة `versionCode` في كل إصدار ونشر ملاحظات الإصدار وchecksums والصور وبيان الخصوصية وقناة للدعم أو issues.

تم حل متطلبات ترخيص Apache-2.0 وتوقيع production المحلي ونشر `main`. وما زال تعارض معرّف التطبيق، ووسم release ‏`v0.1.0`، وبيانات F-Droid، والتحقق من البناء النظيف على Linux/F-Droid وscanner عناصر مانعة.
